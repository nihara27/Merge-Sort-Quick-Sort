2. STABILITY VERIFICATION

Stable Merge Sort preserves the original order of packages with equal weights.

Weight 10: P4 -> P8
Weight 15: P2 -> P5
Weight 20: P1 -> P3 -> P6

Quick Sort does not guarantee that equal-weight packages retain their original order.

3. COMPLEXITY ANALYSIS

Merge Sort:
Best-case time complexity: O(n log n)
Average-case time complexity: O(n log n)
Worst-case time complexity: O(n log n)
Auxiliary space complexity: O(n)

Quick Sort:
Best-case time complexity: O(n log n)
Average-case time complexity: O(n log n)
Worst-case time complexity: O(n^2)
Average auxiliary stack space: O(log n)
Worst-case auxiliary stack space: O(n)

4. COMPARISON TABLE

| Feature | Merge Sort | Quick Sort |
|---|---|---|
| Stability | Stable with the implemented merge rule | Not stable in this implementation |
| Best-case time | O(n log n) | O(n log n) |
| Average-case time | O(n log n) | O(n log n) |
| Worst-case time | O(n log n) | O(n^2) |
| Extra space | O(n) | O(log n) average stack space |
| Equal-weight order | Preserves original order | May change original order |

5. FINAL CONCLUSION

Both Merge Sort and Quick Sort can sort packages by weight in ascending order. Merge Sort is more suitable when the original relative order of packages with equal weights must be maintained because it is stable when equal elements are merged in their original order. It also guarantees O(n log n) time complexity, although it requires O(n) auxiliary space.
